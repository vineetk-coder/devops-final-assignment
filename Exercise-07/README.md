# Exercise-07 — Introduction to Continuous Integration (CI) and Jenkins Installation

**Reference:** `Exercises/7-Jenkins-CI-Automation.md`

## Objective
Understand CI concepts and tools, then install Jenkins with Docker, unlock it with the
initial admin password and reach the dashboard on port 8080.

## Requirements
- Learn: what CI is, key features, benefits, how it works, CI tools, Jenkins concepts
- Install Jenkins: `docker run -d --name jenkins -p 8080:8080 -p 50000:50000 jenkins/jenkins:lts`
- Get the initial password from `/var/jenkins_home/secrets/initialAdminPassword`
- Open `http://localhost:8080/`, unlock, install suggested plugins, create admin user

## Files
| File | Purpose |
|------|---------|
| `scripts/start-jenkins.sh` | Starts (or restarts) the Jenkins container |
| `scripts/get-initial-password.sh` | Prints the unlock password from inside the container |
| `scripts/stop-jenkins.sh` | Stops and removes the container |
| `tests/test_exercise07.py` | Static checks |

## How to run (working directory: `Exercise-07/`)
```bash
docker run -d --name jenkins -p 8080:8080 -p 50000:50000 jenkins/jenkins:lts
docker ps -a
docker exec -it jenkins bash
  cat /var/jenkins_home/secrets/initialAdminPassword
  exit
```
Then browse to **http://localhost:8080/** → paste password → *Install suggested plugins* →
create your own admin user.

Shortcut: `bash scripts/start-jenkins.sh` then `bash scripts/get-initial-password.sh`.
(On Windows PowerShell the `docker` commands work unchanged.)

## CI concepts (summary of the reference notes)

**Continuous Integration** — developers integrate code into a shared repository frequently;
each change triggers an automated build and tests so errors are found early.

**Key features:** frequent integration · automated builds · automated testing · immediate feedback
**Benefits:** early bug detection · better collaboration · faster cycles · higher quality

**How CI works:** developer pushes → CI server detects change → build → tests → feedback.

### CI tools
| Tool | Highlights | Ideal for |
|------|-----------|-----------|
| GitLab CI/CD | Built into GitLab, YAML pipelines, Auto DevOps | GitLab users |
| CircleCI | Cloud, container-based, caching/parallelism | Container workflows |
| Travis CI | YAML config, many languages, GitHub integration | Open-source / small teams |
| Bamboo | Atlassian; JIRA/Bitbucket integration | Atlassian ecosystem |
| TeamCity | JetBrains; rich reports, many runners | Enterprise setups |
| Azure DevOps (Pipelines) | Azure/VS integration, YAML or classic | Azure users |
| GitHub Actions | YAML workflows, marketplace | GitHub users |
| Spinnaker | Multi-cloud CD, canary/blue-green | Cloud-native deployments |
| Buildkite | Hybrid: cloud control + self-hosted agents | Security-sensitive teams |
| Drone | Container-native pipelines, open source | Container-based workflows |

### Jenkins
Open-source automation server for build/test/deploy (CI/CD). Why: automation, CI,
extensibility via plugins, scalability with distributed builds.

**Key concepts:**
1. **Job/Project** — a task Jenkins runs
2. **Build** — compiling/packaging code
3. **Pipeline** — series of build/test/deploy steps
4. **Plugins** — extend functionality (Git, Docker, …)
5. **Nodes** — machines that run jobs (controller/agent)
